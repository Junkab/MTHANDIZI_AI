# MTHANDIZI — Competition Materials

For the ICTAM Malawi Innovative Competition submission. Four documents:

| File | Purpose |
|---|---|
| `ONE_PAGER.md` | Problem, solution, impact, scalability, limitations — the single document to lead with |
| `WHAT_WE_VERIFIED.md` | The evidence trail, curated from `BUILD_LOG.md` — read this to see the engineering is real |
| `DEMO_SCRIPT.md` | What to actually show live, clearly separated from the target end-state vision |
| `LIMITATIONS.md` | Every honest weakness, organized by severity |
| `BILL_OF_MATERIALS.md` | Real Malawi-sourced hardware pricing where available, honestly flagged estimates elsewhere |

## The organizing principle behind all five

Every claim in these documents is either (a) something this project
actually measured or ran, with the evidence in `BUILD_LOG.md`, or (b)
explicitly marked as an estimate, a target, or not-yet-built. Nothing here
implies more than what has actually been proven — the demo script in
particular goes out of its way to separate "here's what's real and running
today" from "here's the vision this is built toward."

**Why this matters for a competition specifically:** a judge who catches an
inflated claim discounts everything else in the submission. A team that
names its own gaps clearly, backed by an unusually thorough evidence trail
for the parts that ARE done, reads as more credible, not less — that's the
bet these documents make.

## Sourcing note

Statistics in `ONE_PAGER.md` (literacy, internet/smartphone penetration,
rural coverage) were researched via web search in September 2026 and are
cited inline with publication dates. `BILL_OF_MATERIALS.md` mixes one
well-sourced figure (tablet pricing, from a Malawi-specific retail listing)
with several explicitly-flagged rough estimates — check that document's
confidence column before using any number in a real budget.
